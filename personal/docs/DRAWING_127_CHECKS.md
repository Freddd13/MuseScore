# R1-C3.1：窗口绘制与连续操作

## 查到的原因

此前强制软件绘制的连续检查，在Qt Quick图片节点访问异常。调用栈经过QMetaObject::cast、QSGSoftwareInternalImageNode::pixmap及软件绘图节点。原代码与修改前的对照版本均曾在这一位置中断。

Qt官方QTBUG-80415已修复同一处纹理释放后仍被读取的问题：纹理引用改为QPointer，在对象销毁后自动清空。本轮将官方提交1c010b202506bb7eb0f0e24ab37ad50e319abada带回当前Qt 5.15.2，只重新编译Qt Quick。来源、校验值、许可和重建步骤见[组件说明](../thirdparty/qtquick/README.md)。

新DLL与原SDK均为Windows x64，全部6724个导出名称一致，其余Qt组件保持。构建后的依赖复制与安装选择同一份修复文件，分别检查组件校验、原SDK校验、不匹配版本、普通构建和带空格目录，共5项通过。Qt SDK原文件保留。

另一个问题发生在首次创建菜单：音源动作依赖尚未赋值的全局主窗口，因此工具栏漏掉入口。现从菜单所属主窗口注册动作；首次入口、图标和实际音源控件已回查。

## 连续操作

使用《如果有来生-release5》的四份独立副本；原文件只读，SHA256前后相同。每份八条240秒测试音频。实际切换标签，用铅笔改选中音的力度，播放六秒，用Ctrl滚轮缩放，并交替打开上下／叠加频谱及独立窗口。

修复后的24轮完成，耗时212.052秒；窗口数保持14。每轮最长界面间隔27.84—51.91毫秒，最后三轮47.04、40.20、42.59毫秒。两组各四次缩放的用时8.36—39.82毫秒。最终进程专用内存约431.6MiB，关闭四谱后约355.1MiB，包含Qt缓存、声音缓冲和保留的撤销内容。

本轮未出现先前的软件绘图异常；自动保存仍按单独任务处理。0.126已捕捉到一次自动保存定时调用290.6毫秒，下一项R1-C3.2继续分解该过程。
